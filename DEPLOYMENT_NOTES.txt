================================================================================
  SoulMap v0.1-preview-board-supabase - 最小部署步驟
================================================================================

📦 此 Release 包含：
  - Supabase PostgreSQL 整合（留言板功能）
  - API 路由 /api/board (GET/POST)
  - localStorage fallback 機制
  - 完整安全措施（RLS + API 驗證 + 速率限制）

================================================================================
  部署前準備
================================================================================

1️⃣ 建立 Supabase 專案
   - 前往 https://supabase.com
   - 建立新專案（選擇 Tokyo 或最近的區域）
   - 等待專案初始化完成（約 1-2 分鐘）

2️⃣ 執行資料庫 Schema
   - 在 Supabase Dashboard 點擊 "SQL Editor"
   - 點擊 "New query"
   - 複製貼上 supabase/schema.sql 的完整內容
   - 點擊 "Run" 執行
   - 驗證：點擊 "Table Editor" 應看到 posts, replies, reactions 三個資料表

3️⃣ 取得 Supabase 憑證
   前往 Supabase Dashboard > Settings > API
   複製以下三個值：

   - Project URL          → NEXT_PUBLIC_SUPABASE_URL
   - anon public key      → NEXT_PUBLIC_SUPABASE_ANON_KEY
   - service_role key     → SUPABASE_SERVICE_ROLE_KEY (選用)

================================================================================
  Vercel Preview 環境部署
================================================================================

步驟 1: 設定環境變數

  前往 Vercel Dashboard
  → 選擇專案 (soulmap)
  → Settings
  → Environment Variables
  → 新增以下三個變數：

  變數名稱: NEXT_PUBLIC_SUPABASE_URL
  值: https://your-project.supabase.co
  環境: ☑ Production  ☑ Preview  ☑ Development

  變數名稱: NEXT_PUBLIC_SUPABASE_ANON_KEY
  值: eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
  環境: ☑ Production  ☑ Preview  ☑ Development

  變數名稱: SUPABASE_SERVICE_ROLE_KEY
  值: eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
  環境: ☑ Production  ☑ Preview  ☑ Development

步驟 2: 部署分支

  方式 A（推薦）- 自動部署：
    git push origin feature/integrated-v1
    → Vercel 會自動偵測並建立 Preview 部署

  方式 B - 手動觸發：
    Vercel Dashboard
    → Deployments
    → 右上角 ... 按鈕
    → Redeploy
    → 選擇 "feature/integrated-v1" 分支
    → Deploy

步驟 3: 驗證部署

  部署完成後：
  1. 開啟 Preview URL (例如: soulmap-xyz.vercel.app)
  2. 前往 /board 頁面
  3. 測試發文功能
  4. 重新整理頁面，確認貼文持久化（資料寫入 Supabase）
  5. 開啟 F12 Console，不應看到「localStorage fallback」警告

================================================================================
  故障排除
================================================================================

❌ 發文後沒有出現在列表中
   → 檢查瀏覽器 Console 是否有錯誤訊息
   → 確認環境變數設定正確（Vercel Dashboard）
   → 確認 Supabase 專案沒有暫停（免費方案閒置 1 週會暫停）

❌ 出現「localStorage fallback」警告
   → 環境變數未設定或設定錯誤
   → 重新部署專案（環境變數變更後需要 Redeploy）

❌ 403 或 401 錯誤
   → 檢查 Supabase RLS 規則是否正確啟用
   → 確認 anon key 設定正確

❌ 速率限制失效
   → 目前使用 in-memory 實作，Serverless 環境下每次請求都是新的 instance
   → 生產環境建議升級至 Redis/Upstash（請參考 SUPABASE_SETUP.md）
